# RUCDAO 项目计划书

> **PoV（Proof of Volunteer）· 志愿服务贡献证明** —— 让每一次志愿服务都被看见、被记录、有回响
> 版本 **v2.0** · 2026-09-23 · 发起：人民大学信息学院志愿服务部
> 配套文档：《01-乡建DAO调研报告》《02-可行性与合规分析》

## 一、背景与问题

人大校内志愿服务存在一个结构性断层：**项目在群里，报名在接龙，记录在 Excel，激励在口头**。学生找不到方向、找不到资源；组织方找不到人、留不住人；时长录入靠人工汇总，一个学期才出证明。

受乡建DAO（ETHShanghai 2026 现场交流启发，详见《01》）"任务帖 + 稻米积分 + 链上徽章"机制启发，我们提出 RUCDAO：**把全校志愿项目整合到一个平台，用 PoV 机制认证每一分钟服务，让志愿时数可信、可查、可累积，并让每一次贡献都有回响。**

## 二、定位：RUCOIN 就是志愿时数的认证方式

**一句话**：RUCOIN（米粒）是志愿时数的链上认证——**1 小时 = 100 粒，余额即认证时数账本**。学生的 RUCOIN 与志愿时数直接对标：2,340 粒 = 23.4 小时，随时可查、可验、可导出。

为什么用 RUCOIN 而不是一张 Excel：

1. **可信**——每一粒都绑定真实服务记录，链上存证、不可篡改，杜绝"人情时长"；
2. **可查**——余额即账本，每笔增减带存证编号，评审、评优、简历引用都拿得出来；
3. **可累积**——技能型服务、艰苦服务有难度系数加权（1.5 / 2.0），付出的差异被看见；
4. **有回响**——时数不只是一个数字：米粒兑面包券、周边、参访机会，还是社区治理的投票权。

**设计原则三条**（《RUCDAO 社区公约》）：

1. **RUCOIN 对标志愿时数**——由真实服务产出，不与人民币挂钩、不可转让；
2. **时数只按真实服务认证**——负责人确认 + 互评 + 抽检三重把关；
3. **发放规则公开透明、节点共治**——每一分增减可追溯，规则修订 2/3 通过。

## 三、双端产品设计

平台分**学生端**与**发布端**，一个闭环的两端：**发布志愿 → 寻找志愿 → 完成服务 → 时数认证 → 兑权益**。

### 3.1 学生端（找志愿、做志愿、攒时数）

| 模块 | 功能 |
|---|---|
| 广场 | 任务帖 / 招募帖信息流（乡建DAO 悬赏体：内容 / 要求 / 赏金），接单即领 |
| 项目库 | 全校项目聚合，按领域（支教/环保/助老/赛会/技能/乡村）筛选，一键报名；每张卡明示「粒数 ≈ 时数」 |
| 我的 | **认证时数账本**（RUCOIN 余额 = 时数）、服务记录、荣誉徽章、券包、志愿北京同步状态 |
| 权益商店 | 米粒兑面包券/咖啡券/打印券/周边/参访名额/年度奖杯；券一次性核销 |

### 3.2 发布端（发布志愿、确认服务、认证时数）

| 模块 | 功能 |
|---|---|
| 发布台 | 发布志愿项目/悬赏任务：领域、岗位数、单人时长、难度系数，**预估发放自动折算「粒 = 小时」**；勾选即同步志愿北京建项 |
| 项目管理 | 报名名单、服务记录确认（负责人点名式确认）、确认后转发放台 |
| 发放台 | **一键发放**：确认记录 → RUCOIN 入账（= 时数认证）→ 链上存证 → 志愿北京批量录入。四步合一 |

**发布节点**：院系志协、学生社团、校级组织、审核过的校外合作机构。

### 3.3 核心闭环

```
发布端建项（同步志愿北京）→ 学生端浏览/报名 → 参与打卡
→ 发布端确认服务记录 → 发放台一键发放：RUCOIN 入账 + 链上存证 + 志愿北京录入
→ 学生端消费：兑面包券/周边/机会，或攒着换参访名额、年度荣誉
```

### 3.4 内容模型（Phase 1 在 WordPress 落地）

| 类型 | 字段（节选） |
|---|---|
| 志愿项目 `ruc_project` | 标题、简介、领域、地点、起止、岗位数、时长/岗位、难度系数、粒数（自动 = 时长×100×系数）、发布节点、志愿北京项目 ID |
| 悬赏任务 `ruc_task` | 【任务】标题、内容、要求、交付方式、赏金粒数、截止时间 |
| 服务记录 `ruc_record` | 志愿者、项目、岗位、实际时长、确认人、录入状态、流水号（链上存证） |
| 券/权益 `ruc_reward` | 名称、所需粒数、券源商户、核销规则、核销码 |
| 徽章 `ruc_badge` | 名称、授予条件、发行量、持有人（链上不可转让徽章） |
| 提案 `ruc_proposal` | 标题、正文、发起节点、2/3 通过线 |

## 四、PoV 机制（Proof of Volunteer）

### 4.1 四步运转

```
① 服务 → ② 存证（核验 + 链上存证 + 志愿北京同步）→ ③ 认证（RUCOIN 入账，1 小时 = 100 粒）→ ④ 回响（券 / 权益 / 投票权）
```

### 4.2 技术类比（供答辩 / 技术受众）

| PoW（工作量证明） | PoV（志愿服务贡献证明） |
|---|---|
| 以工作量达成可信共识 | 以真实服务达成可信记录 |
| 产出证明：哈希运算 | 产出证明：经核验的服务时长与任务交付 |
| 参与者：算力节点 | 参与者：志愿者（学号实名） |
| 记账方：全球节点共识 | 记账方：各院系志协（Issuer）+ 平台抽检 + 链上存证 |
| 难度调整：全网算力 | 难度系数：技能型 1.5 / 艰苦偏远 2.0 |
| 出块奖励 | 时数认证（RUCOIN 入账） |
| 51% 攻击 | 刷时长 → 三重确认 + 惩罚清零公示 |
| 区块浏览器 | 个人志愿档案 + 时数账本 |

**定义句**：*PoV 是对发放机制的类比命名——RUCOIN 不做哈希运算、不消耗算力、不涉及链上共识竞赛，它是志愿服务记录的链上存证。*

### 4.3 发放规则（1 小时 = 100 粒，系数加权）

| 来源 | 规则 |
|---|---|
| 项目服务 | 时长 × 100 × 难度系数（普通 1.0 / 技能型 1.5 / 艰苦偏远 2.0） |
| 悬赏任务 | 按帖标价（摄影 200、海报 300、活动跟拍 500……对标乡建DAO） |
| 黑客松/竞赛 | 按名次发放 |
| 打赏 | 同学/节点自愿打赏，日上限防刷 |
| 荣誉加成 | 学期全勤、"志愿之星"一次性嘉奖 |

**防刷**：学号一账一号；三重确认（负责人 + 互评 + 抽检）；异常模型告警；查实造假清零 + 公示。

## 五、时数的消费：券与权益

时数是本体，米粒是记法。消耗侧第一张券就是**面包券**——"从一张面包券开始"是产品的冷启动记忆点。

**券结构三要素**：① 商品与券面值由商户以人民币标价、结算；② 券限本人、限时、一次性核销；③ 兑券即销毁米粒（链上记账）。

消耗清单：面包券/食堂券/咖啡券（券源：后勤与商户赞助，商户获客 + 校园公益形象，这是有预算的生意）→ 文创周边 → 打印券/机时 → 名企参访、暑期实践名额 → 年度志愿之星。另有活动费用抵扣、打赏、悬赏发帖。

## 六、技术架构

```
[学生/发布节点] ⇄ RUCDAO 前台（Apple Design System · 响应式 · WCAG 2.1 AA）
                    ⇄ WordPress + RUCDAO Core 插件（内容模型/报名/记录/时数账本/券核销）
                         ├─ 链上存证模块 ⇄ RuCoin.sol（时数账本，测试网 → 校内联盟链）
                         ├─ 志愿北京适配器（建项同步 / 批量录入 / 工时码）
                         └─ 统一身份认证（学号实名）
```

- **前端**：Apple 设计体系（SF Pro 字体栈、4pt 栅格、16px 卡片、毛玻璃导航、Spring 动效、深浅双模式），人大红 `#8C2229` 为品牌主色；图标采用 Remix Icon（本地化，零外部依赖）；
- **产品主体**：WordPress + 自研插件 RUCDAO Core（编辑 = 志协部员，Gutenberg 上手 < 30 分钟），选型论证见《02》第 4 节；
- **链上层**：`contracts/RuCoin.sol`——时数账本合约：`award`（发放）、`redeem`（权益核销销毁）、`recordService`（服务时长存证）、`slash`（作弊查处），**转账永久禁用**（对标时数、不可转让的定位在合约层固化）；
- **钱包体验**：托管钱包默认（学号即账户），可选绑定自有钱包查看存证，杜绝丢私钥丢时数。

## 七、合规与边界

一句话：**RUCOIN 是志愿时数的认证凭证，不是货币**——由真实服务产出、不与人民币双向兑换、不可转让，商品经「券」一层兑换且由商户以人民币结算。志愿时长在志愿北京照实录入，米粒与时数同源同账。其余监管分析与措辞纪律见《02》（含对外文案白/黑名单）。

**统一口径 FAQ**："米粒是钱吗？"——不是。它对标志愿时数：真实服务产出、不可转让、不兑人民币；兑的是面包券、周边和机会。

**生态联动**：与乡建DAO/LXDAO 互学（任务帖联发、黑客松联办、徽章互认探索），把 PoV 输出兄弟高校。

## 九、活动体系：科技走入乡村

对标乡建DAO"数智乡建黑客松"（3 天 133 人 71 方案）：

1. **寒暑假实践 + 黑客松**：软件（村史小程序、AI 助农问答）/ 硬件（助老助残装置）/ 文创（"非遗"数字化）三赛道；线上预热工作坊 → 3 天线下共创（对接龙潭村等真实村庄）→ 赛后孵化；参赛即认证时数 + 荣誉徽章，优秀方案推荐乡建DAO 社区；
2. **校园悬赏【任务】体系**：摄影、海报、排版、维修即发即结（200—500 粒带）；
3. **共学共创**：月度"志愿 × 技术"工作坊。

## 十、组织与治理

- **主办**：信息学院志愿服务部；**共建**：校青年志愿者协会、校团委（立项与监督）；
- **治理**：节点大会（发布节点各一票）+ 贡献加权投票（时数权重封顶）；规则修订 2/3 通过；
- **争议**：仲裁委员会 5 人（志协 2 + 老师 1 + 学生代表 2），7 日内裁定。
