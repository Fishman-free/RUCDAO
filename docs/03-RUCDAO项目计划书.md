# RUCDAO 项目计划书

> 人大校内志愿服务的"操作系统"——项目聚合 · 贡献上链 · 权益循环
> 版本 v0.1 · 2026-09-23 · 发起：人民大学信息学院志愿服务部
> 配套文档：《01-乡建DAO调研报告》《02-可行性与合规分析》

## 一、背景与问题

人大校内志愿服务存在一个结构性断层：**项目在群里，报名在接龙，记录在 Excel，激励在口头**。学生找不到方向（不知道有什么项目适合自己）、找不到资源（好项目沉在各院系公众号里）；组织方（院系志协、社团、校外合作机构）找不到人、留不住人；时长录入靠人工汇总，一个学期才出证明。

受乡建DAO（ETHShanghai 2026 现场交流启发，详见调研报告）"任务帖 + 稻米积分 + 链上徽章"机制的启发，我们提出 RUCDAO：**把全校志愿项目整合到一个平台，用"米粒（RUCOIN）"记录每一分钟贡献，用链上凭证沉淀每一份荣誉，并与志愿北京时长体系打通。**

## 二、愿景与定位

- **愿景**：让每一次志愿服务都被看见、被记录、有回响。
- **定位**：人大校内志愿服务的"操作系统"——项目聚合平台 + 贡献凭证体系 + 权益循环 + 志愿文化社区。
- **RUCOIN（米粒）**：人大学生志愿服务的贡献凭证。命名取"米"呼应乡建DAO 稻米，"粒"寓意**颗粒归仓、涓滴成河**：每一次服务、每一项技能、每一份创意都折算成米粒，永久存证。
- **三条铁律**（写进《RUCDAO 社区公约》）：
  1. 米粒**不可转让、不可交易、不可兑换现金**——它是贡献记录，不是货币；
  2. 志愿时长**只按真实服务如实录入**——米粒不买时长，只兑换权益与机会；
  3. 发放规则**公开透明、节点共治**——米粒的每一分增减都可在链上与平台追溯。

## 三、产品设计

### 3.1 用户角色

| 角色 | 是谁 | 核心动作 |
|---|---|---|
| 志愿者 | 全校学生（学号实名注册） | 浏览项目 → 报名 → 参与/打卡 → 时长确认 → 收米粒 → 兑权益 |
| 发布节点 | 院系志协、学生社团、校级组织、审核过的校外合作机构 | 发布项目/任务帖 → 管理报名 → 确认服务 → 发米粒 |
| 平台运营 | 信息学院志愿服务部 | 审核节点/项目、异常巡检、权益上架、数据看板 |
| 仲裁委员会 | 志协 + 指导老师 + 学生代表 | 争议裁定、作弊查处、规则修订提案 |

### 3.2 核心流程

```
发布节点建项（同步志愿北京建项）
   → 广场/项目库曝光（标签：支教/环保/助老/赛会/技能/乡村……）
   → 学生报名（米粒 ≥ 阈值可抢稀缺名额）
   → 参与打卡（负责人确认 + 学生互评）
   → 服务记录生成：志愿北京时长录入（直通车）＋ 米粒入账（链上存证）
   → 米粒消费：权益商店 / 活动费用抵扣 / 打赏 / 悬赏接单
   → 荣誉沉淀：SBT 徽章、年度志愿档案（可导出 PDF / 简历引用）
```

### 3.3 内容模型（Phase 1 在 WordPress 中落地）

| 类型 | 字段（节选） | 说明 |
|---|---|---|
| 志愿项目 Project | 标题、简介、领域标签、服务对象、地点、起止时间、岗位数、时长/岗位、米粒/时长、发布节点、志愿北京项目 ID | CPT `ruc_project` |
| 悬赏任务 Task | 【任务】标题、内容、要求、交付方式、赏金米粒、截止时间 | CPT `ruc_task`（乡建DAO 任务帖体） |
| 服务记录 ServiceRecord | 志愿者、项目、岗位、实际时长、确认人、志愿北京录入状态、米粒流水号 | 自定义表 + 链上存证 |
| 权益 Reward | 名称、所需米粒、库存、兑换规则、核销方式 | CPT `ruc_reward`（权益商店） |
| 徽章 Badge | 名称、授予条件、发行量、持有人 | SBT 合约 + 展示页 |
| 提案 Proposal | 标题、正文、发起节点、投票权规则、2/3 通过线 | 对标乡建DAO 公约第 24 条 |

### 3.4 米粒经济（发放与消耗）

**发放（预估基准：1 服务时长 = 100 米粒）**

| 来源 | 规则 |
|---|---|
| 项目服务 | 时长 × 100 × 难度系数（普通 1.0 / 技能型 1.5 / 艰苦偏远 2.0） |
| 悬赏任务 | 按帖标价（摄影 200、海报 300、活动跟拍 500……对标乡建DAO 样例） |
| 黑客松/竞赛 | 按名次发放（见第六节活动体系） |
| 打赏 | 同学/节点自愿打赏，日上限防刷 |
| 荣誉加成 | 学期全勤、"志愿之星"一次性嘉奖 |

**消耗**：权益商店兑换、活动费用抵扣、悬赏发帖保证金、打赏。**米粒只减不回法币**，学期不做清零（长期主义），但毕业时可铸造"毕业志愿档案 SBT"作为永久纪念。

**防刷**：学号一账一号；服务记录三重确认（负责人 + 学生互评 + 平台抽检）；异常模型告警；查实造假**米粒清零 + 公示**（写进公约）。

## 四、技术架构

### 4.1 总体架构（Phase 1）

```
[学生/节点] ⇄ WordPress 前台（RUCDAO 主题，响应式 / WCAG 2.1 AA）
                 ⇄ RUCDAO Core 插件（内容模型 / 报名 / 记录 / 米粒账本 / 权益商店）
                      ├─ 链上存证模块 ⇄ RuCoin.sol（SBT 贡献凭证账本，测试网→校内联盟链）
                      ├─ 志愿北京适配器（建项同步 / 时长批量录入 / 工时码）
                      └─ 统一身份认证适配（学号实名）
```

- **产品主体**：WordPress（编辑 = 志协部员，Gutenberg 上手 < 30 分钟）+ 自研插件 `RUCDAO Core` + 自定义主题（人大红 × 宣纸米白 × 稻穗印章视觉体系）。选型论证见《02》第 4 节。
- **链上层**：`contracts/RuCoin.sol`——灵魂绑定的贡献凭证账本：`award`（节点发放）、`redeem`（权益核销销毁）、`recordService`（服务时长存证），**`transfer` 永久 revert**。发行权角色化（校志协 + 院系志协），全程无融资、无交易、无法币出口。
- **钱包体验**：默认托管钱包（学号即账户），进阶用户可绑定 MetaMask 自有钱包（签名验证），杜绝"丢私钥丢米粒"。

## 五、合规与风控

（全文见《02-可行性与合规分析》，此处摘要）

1. 米粒定性为**不可转让的志愿服务贡献凭证**，无现金兑换、无二级市场、无融资属性；
2. 志愿时长**照实录入志愿北京**，米粒只兑换权益/机会，绝不"买时长"；
3. 校团委/校志协**立项背书**先行，平台规则以《RUCDAO 社区公约》固化（节点、发放、处罚、仲裁、2/3 修订）；
4. 对外传播统一口径：**"志愿服务贡献积分/凭证"**，不使用"代币/发币/上链炒"等措辞。

## 六、活动体系：科技走入乡村 + 校园悬赏

对标乡建DAO"数智乡建黑客松"（3 天 133 人 71 方案、软硬件文创三赛道）：

1. **"科技走入乡村"寒暑假实践 + 黑客松**（旗舰活动）：
   - 赛道：软件（村史小程序、AI 助农问答、留守儿童编程课）/ 硬件（低成本助老助残装置）/ 文创（"非遗"数字化、乡村 IP 设计）；
   - 形式：线上预热系列工作坊（信院技术栈免费教学）→ 3 天线下共创（对接乡建DAO/龙潭村等真实村庄需求）→ 赛后落地孵化；
   - 激励：参赛即得米粒 + 志愿北京时长（按真实服务）+ SBT"数字村民之友"徽章 + 落地项目持续计酬；优秀方案推荐至乡建DAO 社区与"数智乡建黑客松"。
2. **校园悬赏【任务】体系**（日常引流）：活动跟拍、海报设计、推送排版、设备维修、电脑义诊……即发即接即结算，参照乡建DAO 200—1000 稻米的定价带。
3. **共学共创**：每月一次"志愿 × 技术"公开工作坊，产出直接进入项目库。

## 七、组织与治理

- **主办**：信息学院志愿服务部；**共建**：校青年志愿者协会（校志协）、校团委（立项与监督）；
- **指导**：校团委老师 + 信息学院专业教师（技术顾问）；
- **治理**：节点大会（发布节点各一票）+ 贡献加权投票（米粒权重封顶，防财阀）；规则修订 2/3 通过（对标乡建DAO 公约）；
- **争议**：仲裁委员会 5 人（志协 2 + 老师 1 + 学生代表 2），7 日内裁定；
- **生态联动**：与乡建DAO、LXDAO 等社区互学（任务帖联发、黑客松联办、徽章互认探索）。
