# RUCDAO 项目计划书

> **PoV（Proof of Volunteer）· 志愿服务贡献证明** —— 让每一次志愿服务都被看见、被记录、有回响
> 版本 v1.0 · 2026-09-23 · 发起：人民大学信息学院志愿服务部
> 配套文档：《01-乡建DAO调研报告》《02-可行性与合规分析》

## 一、背景与问题

人大校内志愿服务存在一个结构性断层：**项目在群里，报名在接龙，记录在 Excel，激励在口头**。学生找不到方向（不知道有什么项目适合自己）、找不到资源（好项目沉在各院系公众号里）；组织方（院系志协、社团、校外合作机构）找不到人、留不住人；时长录入靠人工汇总，一个学期才出证明。

受乡建DAO（ETHShanghai 2026 现场交流启发，详见《01》）"任务帖 + 稻米积分 + 链上徽章"机制启发，我们提出 RUCDAO：**把全校志愿项目整合到一个平台，以 PoV 机制记录每一分钟贡献，用米粒（RUCOIN）沉淀每一份付出，并与志愿北京时长体系打通。**

## 二、愿景与定位：PoV

- **愿景**：让每一次志愿服务都被看见、被记录、有回响。
- **核心概念——PoV（Proof of Volunteer，志愿服务贡献证明）**：做志愿本身就是"产出证明"的过程——服务被核验，记录被存证，贡献被计量，权益有回响。**PoV 是我们对外推广的旗帜性概念。**
- **定义句**（所有材料统一口径）：*PoV 是对发放机制的类比命名——RUCOIN 不做哈希运算、不消耗算力、不涉及链上共识竞赛，它是志愿服务记录的链上存证。*
- **RUCOIN（米粒）**：志愿服务贡献积分/凭证。命名取"米"呼应乡建DAO 稻米，"粒"寓意**颗粒归仓、涓滴成河**：每小时服务、每项技能、每份创意都折算成米粒。
- **三条铁律**（写进《RUCDAO 社区公约》）：
  1. **米粒与人民币不挂钩**——不可用人民币充值购买、不可转让、不可兑换现金；
  2. **志愿时长只按真实服务如实录入**——米粒不买时长，只兑换券与权益；
  3. **发放规则公开透明、节点共治**——每一分增减可追溯。

## 三、PoV 机制设计

### 3.1 四步运转

```
① 服务：报名项目、真实参与，负责人确认到岗与工时
② 存证：服务记录经核验后链上存证（PoV 核验），志愿北京同步时长
③ 米粒：按时长 × 难度系数发放（1 小时 = 100 粒 × 系数）
④ 回响：米粒兑面包券/周边/机会，也是社区提案的投票权
```

### 3.2 为什么叫"贡献证明"（技术类比，供答辩/技术受众使用）

| PoW（工作量证明） | PoV（志愿服务贡献证明） |
|---|---|
| 机制目标：以工作量达成可信共识 | 机制目标：以真实服务达成可信记录 |
| 产出证明：哈希运算 | 产出证明：经核验的服务时长与任务交付 |
| 参与者：算力节点 | 参与者：志愿者（学号实名，防女巫） |
| 记账方：全球节点共识 | 记账方：各院系志协（Issuer）+ 平台抽检 + 链上存证 |
| 难度调整：全网算力 | 难度系数：技能型 1.5 / 艰苦偏远 2.0 |
| 产出奖励：区块奖励 | 产出奖励：米粒 |
| 攻击与防御：51% 攻击 | "攻击"是刷时长/卖时长 → 三重确认 + 惩罚清零公示 |
| 可查证性：区块浏览器 | 可查证性：个人志愿档案 + 米粒账本 |

### 3.3 发放规则（基准：1 服务小时 = 100 粒）

| 来源 | 规则 |
|---|---|
| 项目服务 | 时长 × 100 × 难度系数（普通 1.0 / 技能型 1.5 / 艰苦偏远 2.0） |
| 悬赏任务 | 按帖标价（摄影 200、海报 300、活动跟拍 500……对标乡建DAO 任务帖） |
| 黑客松/竞赛 | 按名次发放 |
| 打赏 | 同学/节点自愿打赏，日上限防刷 |
| 荣誉加成 | 学期全勤、"志愿之星"一次性嘉奖 |

## 四、产品设计

### 4.1 用户角色

| 角色 | 是谁 | 核心动作 |
|---|---|---|
| 志愿者 | 全校学生（学号实名注册） | 浏览 → 报名 → 参与/打卡 → 时长确认 → 收米粒 → 兑券/权益 |
| 发布节点 | 院系志协、社团、校级组织、审核过的校外合作机构 | 发布项目/任务帖 → 管理报名 → 确认服务 → 发米粒 |
| 平台运营 | 信息学院志愿服务部 | 审核节点/项目、异常巡检、券源谈判、数据看板 |
| 仲裁委员会 | 志协 + 指导老师 + 学生代表 | 争议裁定、作弊查处、规则修订提案 |

### 4.2 核心流程

```
发布节点建项（同步志愿北京建项）
  → 广场/项目库曝光（标签：支教/环保/助老/赛会/技能/乡村……）
  → 学生报名（米粒达阈值可优先抢稀缺名额）
  → 参与打卡（负责人确认 + 学生互评）
  → 服务记录生成：志愿北京时长录入（直通车）＋ 米粒入账（链上存证）
  → 米粒消费：兑面包券等消费券 / 权益商店 / 活动费用抵扣 / 打赏 / 悬赏
  → 荣誉沉淀：SBT 徽章、年度志愿档案（可导出 PDF / 简历引用）
```

### 4.3 内容模型（Phase 1 在 WordPress 中落地）

| 类型 | 字段（节选） | 说明 |
|---|---|---|
| 志愿项目 Project | 标题、简介、领域标签、服务对象、地点、起止时间、岗位数、时长/岗位、米粒/时长、发布节点、志愿北京项目 ID | CPT `ruc_project` |
| 悬赏任务 Task | 【任务】标题、内容、要求、交付方式、赏金米粒、截止时间 | CPT `ruc_task`（乡建DAO 任务帖体） |
| 服务记录 ServiceRecord | 志愿者、项目、岗位、实际时长、确认人、志愿北京录入状态、米粒流水号 | 自定义表 + 链上存证 |
| 券/权益 Voucher | 名称、所需米粒、券源商户、核销规则（限本人/限时/一次性）、核销码 | CPT `ruc_reward`（券包与权益商店） |
| 徽章 Badge | 名称、授予条件、发行量、持有人 | SBT 合约 + 展示页 |
| 提案 Proposal | 标题、正文、发起节点、投票权规则、2/3 通过线 | 对标乡建DAO 公约第 24 条 |

## 五、米粒经济（人民币不挂钩）

**发放**：见 3.3。**消耗侧的第一张券，就是面包券**——"从一张面包券开始"是产品的冷启动叙事，也是 PoV 推广的记忆点。

### 5.1 券结构三要素（缺一不可）

1. **商品与券面值由商户以人民币标价、结算**——米粒与人民币不挂钩，商品永远不以米粒计价；
2. **券限本人、限时、一次性核销**（到店出示核销码）——券不可转让，杜绝券变相流通；
3. **兑券即销毁米粒**（链上 `redeem` 记账）——米粒只减不增于消费侧，无任何现金出口。

消耗清单：面包券/食堂券/咖啡券（券源：后勤与商户赞助）→ 文创周边 → 打印券/机时 → 名企参访、暑期实践名额 → 年度志愿之星。另有活动费用抵扣、打赏、悬赏发帖。

**防刷**：学号一账一号；服务记录三重确认（负责人 + 学生互评 + 平台抽检）；异常模型告警；查实造假**米粒清零 + 公示**（写进公约）。

## 六、合规与风控（详见《02》）

1. **三条设计特征**：米粒不可充值购买、不可转让、商品不以米粒计价——这是"没事"的真正原因，**与"是否流出校外"无关**（校内封闭不构成豁免）；
2. **时长照实录入志愿北京**，米粒只兑券/权益，绝不"买时长"；
3. **措辞纪律**（白名单/黑名单见《02》2.4）：对外只说"PoV 志愿服务贡献证明、米粒、兑券"，禁用炒作语汇；
4. **校团委/校志协立项背书先行**，规则以《RUCDAO 社区公约》固化。

**统一口径 FAQ**（宣讲必答）："米粒是钱吗？"——**不是。它与人民币不挂钩、不能充值、不能转让、不能换钱；它换的是面包券、周边和机会，本质是一份可查证的贡献记录。**

**生态联动**：与乡建DAO/LXDAO 互学（任务帖联发、黑客松联办、徽章互认探索），把 PoV 概念向兄弟高校输出。

## 八、组织与治理

- **主办**：信息学院志愿服务部；**共建**：校青年志愿者协会、校团委（立项与监督）；
- **指导**：校团委老师 + 信息学院专业教师（技术顾问）；
- **治理**：节点大会（发布节点各一票）+ 贡献加权投票（米粒权重封顶，防"一言堂"）；规则修订 2/3 通过（对标乡建DAO 公约）；
- **争议**：仲裁委员会 5 人（志协 2 + 老师 1 + 学生代表 2），7 日内裁定。

## 十一、风险与应对（摘要）

| 风险 | 应对 |
|---|---|
| 被误读为"发币" | 定义句 + 三条铁律 + 立项先行 + 措辞黑名单 |
| 刷时长/卖时长 | 三重确认 + 异常告警 + 清零公示 |
| 券源不稳定 | 商户共赢话术（获客 + 校园公益形象），先签面包房试点再复制 |
| 冷启动 | 存量项目搬迁 + 悬赏任务引流 + "从一张面包券开始"记忆点 |
| 换届时效断档 | 开源 + 文档 + 与技术类社团共建 |

---

**一句话总结**：RUCDAO 用 **PoV（志愿服务贡献证明）** 记录真实服务，用**米粒**计量贡献、用**面包券**开启回馈——**不挂钩人民币、不买时长、不碰现金**，让每一次志愿服务都被看见、被记录、有回响。
