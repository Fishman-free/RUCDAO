# RUCDAO 可行性与合规分析

> 2026-09-23 · 结论先行版 · 配套文档：《01-乡建DAO调研报告》《03-RUCDAO项目计划书》

## 0. 结论先行

| 原始设想 | 裁决 | 一句话理由 |
|---|---|---|
| 所有志愿项目整合到 RUCDAO 平台，学生自由浏览、报名、参与 | ✅ **完全可行，且最该做** | 纯信息与流程系统，无合规障碍，直接解决"找不到方向、找不到资源" |
| 参与后发放链上代币 RUCOIN（对标稻米） | ✅ **可行，前提是定性为"不可转让贡献凭证/积分"** | 乡建DAO 稻米本身就是积分；链上部分做**存证与荣誉身份**，不做金融 |
| RUCOIN 兑换志愿北京时数 | ⚠️ **必须重新定义：不是"兑换"，是"打通录入"** | 志愿时长只能基于**真实服务**记录，"用币买时长"会被定性为买卖志愿时长（灰产，学籍/评优风险） |
| RUCOIN 兑换现金 | ❌ **红线，砍掉** | RUCOIN 兑换法币 = 虚拟货币兑换业务 = 非法金融活动（2021 十部委通知、2026 八部门通知），学校绝无可能背书 |
| RUCOIN 支付社区活动费用 | ✅ **可行（保留）** | 社区内积分抵扣，与乡建DAO 稻米用途一致，不涉及法币双向兑换 |
| 模仿乡建DAO 黑客松办"科技走入乡村"活动并发 RUCOIN | ✅ **完全可行** | 对标数智乡建黑客松，属活动运营 + 积分激励，风险极低、传播价值极高 |

**总评**：这个方向**可行**——把 RUCDAO 做成"人大校内志愿服务的操作系统 + 贡献凭证体系"，把"发币、买时长、换现金"这三个金融化想象替换成"链上贡献存证 + 志愿北京录入直通车 + 权益商店"。下面给出依据。

## 1. 真实痛点（为什么值得做）

1. **信息不对称**：志愿项目散落在公众号推文、微信群、班群接龙里，学生"想找的时候找不到，不想找时天天被刷屏"。
2. **链路断裂**：报名（群接龙）→ 参与（签到纸）→ 时长录入（Excel 汇总给志协）→ 证明（等一个学期）四段式流程，每段都在丢数据、都在等。
3. **激励缺位**：干多干少一个样，零散技能型志愿（拍视频、做海报、修电脑）没有被定价和记录，学生没有持续参与的动力。
4. **沉淀为零**：每一届志愿服务部都在重复造轮子，项目经验、合作关系、执行手册不留痕。

RUCDAO 用一个平台 + 一套贡献凭证把这四个痛点串起来——这正是乡建DAO 用"稻米 + 任务帖"在乡村场景验证过的路径。

## 2. 合规红线（必须逐条守住）

### 2.1 虚拟货币监管：RUCOIN 不能有"钱味"

- 《关于防范代币发行融资风险的公告》（2017，七部委）：代币发行融资（ICO）属非法公开融资，一律严格禁止。
- 《关于进一步防范和处置虚拟货币交易炒作风险的通知》（2021-09，十部委，gov.cn：https://www.gov.cn/zhengce/zhengceku/2021-10/08/content_5641404.htm ）：**虚拟货币与法定货币之间的兑换业务、虚拟货币之间的兑换业务、代币发行融资等均属非法金融活动**，一律严格禁止、依法取缔。
- 《关于进一步防范和处置虚拟货币等相关风险的通知》（2026-02，八部门）：**重申境内对虚拟货币坚持禁止性政策**，虚拟货币相关业务活动属于非法金融活动。

**推论**："RUCOIN 兑换现金"意味着平台（哪怕只是撮合）从事法币与代币的兑换，直接落入非法金融活动范畴；若 RUCOIN 可转让、有价格预期，还可能被认定为变相代币发行。**结论：现金兑换必须砍掉，且 RUCOIN 必须设计为不可转让、无二级市场、不承诺任何法币价值。**

### 2.2 志愿服务规则：时长不能"兑换"，只能"记录"

- 志愿时长的法定载体是"志愿北京"（bv2008.cn，北京市志愿服务联合会运行）：项目须由**注册志愿服务组织**发布，时长录入方式为**①组织方在项目结束后录入，②平台生成工时码由志愿者自主录入**，原则是"有服务必录入"。
- 时长的本质是**服务记录证明**，不是积分。"用 RUCOIN 换时长"= 出钱/出币购买服务证明 = 买卖志愿时长，是教育系统明令打击的灰产，一经查实会影响综测、评优甚至学籍处分。

**推论**：正确姿势是把"兑换时长"重构为"**录入直通车**"——RUCOIN 不买时长，而是：①平台项目直连志愿北京建项与录入；②参与即记录、按真实服务如实录入；③RUCOIN 的作用是**优先报名权、匹配加速、技能认证**（时长本体永远照实）。

### 2.3 校内治理

- 项目需校团委/校青协（校志协）**立项背书**，信息学院志愿服务部作为运营主体；发布方实名认证（校内组织 + 合作机构审核）。
- 明确《RUCDAO 社区公约》：节点（院系志协/社团/合作机构）、米粒发放规则、作弊处罚（刷时长/卖时长一经查实清零并公示）、争议仲裁。

## 3. 兑换体系重构（原需求 → 合规替代）

| 原设想 | 重构后 | 说明 |
|---|---|---|
| RUCOIN → 现金 | ❌ 删除，替换为 **权益商店**：校园文创周边、食堂/咖啡券、打印券、活动经费抵扣、机房机时、技能培训名额、名企参访名额、暑期实践名额、"志愿之星"年度奖品 | 权益由志协经费/赞助/学校资源供给，**只减米粒、不涉及一分钱法币流出** |
| RUCOIN → 志愿北京时数 | ⚠️ → **录入直通车**：项目在志愿北京同步建项，服务结束由项目负责人审核 + 批量录入（或工时码）；米粒兑换的是"**优先报名权/稀缺项目名额/认证徽章**"，时长照实 | 解决真痛点（时长录入慢、证明难拿），又不触红线 |
| RUCOIN → 支付活动费用 | ✅ 保留：讲座、工作坊、出游、聚餐的报名费/材料费用米粒抵扣或全免 | 社区内循环，对标乡建DAO 稻米用途 |
| （新增） | **打赏与悬赏**：对优质内容/紧急任务发米粒悬赏（【任务】帖），同学间打赏 | 直接移植乡建DAO 任务帖玩法，冷启动神器 |
| （新增） | **SBT 徽章 + 治理投票**：星级志愿者/技能徽章（链上不可转让），提案投票权重与贡献挂钩 | 对标《乡建DAO社区公约》第 20 条与南塘豆投票权 |

## 4. 技术可行性：三个方案对比

| 维度 | A. WordPress + 自研插件 RUCDAO Core | B. Next.js + 自研后端（全自研 dApp） | C. Fork Bluesky/ATProto（照搬 xjdao.xyz） |
|---|---|---|---|
| 与需求匹配 | ★★★★★ 项目发布=内容模型，报名/表单/兑换生态现成 | ★★★★ 需要从零做后台与权限 | ★★★ 它是社交广场，不是项目管理系统 |
| 编辑体验（部员运营） | ★★★★★ Gutenberg 后台，非技术同学 30 分钟上手 | ★★ 需自建管理端 | ★★ 运营在协议层之上无后台 |
| Web3 层 | ✅ 插件内做钱包绑定 + 链上存证/徽章合约 | ✅ 原生集成 | ✅ 社交身份 ATProto + 另接合约 |
| 对接志愿北京 | ✅ 插件做导出/工时码适配器 | 需自研 | 需自研 |
| 开发成本（学生团队） | 低—中（PHP 插件 + 少量 JS） | 高（前后端 + 运维） | 很高（协议栈复杂） |
| 长期维护 | 插件化、主题化，交接成本低 | 依赖开发者文档 | 协议栈人才稀缺 |

**推荐：A（WordPress + RUCDAO Core 插件）为产品主体，链上层独立成合约（见 contracts/RuCoin.sol）。** 理由：RUCDAO 的本质是"项目管理 + 记录 + 激励"，是 CMS/内容模型问题，不是社交协议问题；乡建DAO 用 ATProto 是因为它要做"广场社区"，我们要做的是"志愿操作系统"。若未来要做校际社区广场，可在 Phase 3 再引入 ATProto。

**链上层设计**（合规优先）：

- RUCOIN = **链上贡献凭证账本**（灵魂绑定：`transfer` 直接 revert），记录"发放/核销/服务存证"三类事件；
- 发放权（Issuer）= 校志协 + 各院系志愿服务部多签/角色，**不由个人任意增发**；
- 部署路径：**测试网演示 → 校内联盟链/BSN 存证（可选）**，全程不发币融资、不开交易对、不承诺法币价值；
- 私钥体验降级：支持"托管钱包 + 签名绑定自有钱包"双轨，避免学生丢私钥导致米粒丢失。

## 5. 风险清单与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 被误读为"发币"，学校叫停 | 高 | 对外一律称"志愿服务贡献积分/凭证（米粒）"；白皮书/计划书里明示不可转让、无现金出口；先拿团委立项 |
| 买卖/刷志愿时长 | 高 | 时长只按真实服务录入 + 项目负责人审核 + 异常模型（同 IP 批量签到、时长/人次异常）告警 + 作弊清零公示 |
| 现金兑换诉求强烈（同学的真实需求） | 中 | 用权益商店承接"米粒换好处"；把"缺钱"的真问题引导到勤工助学/奖学金等正规渠道 |
| 冷启动（没项目、没学生） | 中 | 先把志愿服务部自己经手的 20+ 存量项目搬上来；任务帖悬赏（摄影/海报/文案）先行引流 |
| 私钥丢失/钓鱼 | 中 | 托管钱包默认 + 自有钱包签名绑定可选；发放以服务记录为源，链上仅存证，凭证可补发 |
| 女巫攻击（多号薅米粒） | 中 | 校内统一身份认证（学号）实名注册，一号一钱包绑定 |
| 平台无人维护（换届断档） | 中 | 代码开源到 GitHub（本仓库）+ 文档化 + 与校计算爱好者协会/信院技术部共建 |

## 6. 最终裁决

**可行，做。** 但落地形态是：

> **RUCDAO = 志愿项目聚合平台（WordPress + RUCDAO Core）+ 米粒贡献凭证体系（不可转让积分 + SBT 徽章 + 链上存证）+ 志愿北京录入直通车 + 权益商店 + "科技走入乡村"黑客松。**

砍掉的是"法币兑换"和"代币买时长"；换回来的是一个学校敢背书、同学真受益、机制可持续的系统。详见《03-RUCDAO项目计划书》。
